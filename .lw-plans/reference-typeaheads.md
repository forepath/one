# Reference typeaheads (2026-10-29, user)

> "The 'Create' forms with the stepper in Loadweaver require some secret references and other references to be added.
> Right now I have to input raw values. This should be done with a typeahead that respects the user's limitations
> accordingly. This applies to all fields of that kind regardless of in which application they show up."

Status: Loadweaver implemented (generated resource form + Git connection credentials). Decabill implemented (section 4). Agenstra
implemented (section 3).

## 1. The existing pattern

**Shell:** `fpc-typeahead-select` (`libs/domains/shared/frontend/ui-components/src/lib/typeahead-select/`). It is
purely presentational. It owns the query input (`[(query)]`), `[(open)]`, `loading` (results host hidden while loading,
so the empty state can't flash), `openOnFocus`, `clearable` + `(cleared)`, `size`, and the `menu` (body-portaled,
`position: fixed`, safe inside modals) or `inline` variant. The consumer projects the suggestion list
(`[fpcTypeaheadSuggestions]`) and optionally a selection (`[fpcTypeaheadSelection]`).

**Decabill wrappers** (`billing-admin-user-select`, `-subscription-select`, `-supplier-select`,
`-supplier-contract-select`, `project-milestone-select`; Agenstra `agent-select` and `client-select` are the same):

- `model()` holds the stored id. Optional inputs: a preloaded list (resolves the label), a scope id (`userId`,
  `supplierId`, `projectId`), `size`, `disabled`, `required`, `placeholder`, `showSuggestionsOnFocus`, and
  `suggestionLimit` (20).
- Search: `toObservable(query)` → `skip(1)` → `debounceTime(300)` → `distinctUntilChanged` → `switchMap` to the
  server list call with `{ search, limit }`. Errors are swallowed with `catchError(() => of([]))`; `takeUntilDestroyed`.
- Suggestions are `(mousedown)` `dropdown-item` buttons: the label, plus a monospace id / detail line.
- Selected: the input is replaced by an `fpc-badge` chip with the label and a `btn-close` (clear).
- Empty state: "No … found." when the term is non-empty, nothing came back, and nothing is loading.
- There is no create-new option and no explicit "no access" handling (an error is an empty list). The lists are
  admin-only APIs on admin pages.

**Loadweaver variant** (`objects/reference-field.component.ts`, 2026-10-29). Loadweaver references are names that the
YAML must hold verbatim, so the field is a free-text combobox, not a chip:

- The input shows the stored value.
- Focus lists what the caller can see at once.
- Typing writes the value right away (YAML two-way sync) and asks the server after 250 ms (`switchMap` + `timer`).
- 401 / 403 sets `denied`: the menu stays closed and a hint "type the name" shows. It is never an error.
- The empty state names the kind (and project) and says "You can still type a name."

The shared component was not changed: no generic capability was missing.

### 2.3 Secrets: DONE (2026-10-29, names-only endpoint added by the user's agent)

The console has no data-access call that lists secret names. No Loadweaver UI calls a secrets endpoint, and creating
one would need the protected secrets controller / service, which this work must not touch. So secret references are a
**project typeahead** (scoped: the caller's projects + readable `Project`s; default = the edited resource's / the
connection's project) plus a **typed name**. The result is `secret://<project>/<name>`. Secret names and values are
never requested; the specs assert that no `/secret` URL is called.

Decision needed: should the secrets owner add a names-only list (`GET /secrets?project=&q=&limit=` → `{ name, keys?,
updatedAt }`, readers of the project, never values)? With that, the name input becomes a second typeahead (and a key
typeahead if keys are returned). The UI is already split into project + name for this.
