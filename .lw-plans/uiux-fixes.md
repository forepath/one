# UI / UX sweep: findings (2026-10-29)

- **Scope**: the consoles of Decabill (`apps/decabill/frontend-billing-console`), Agenstra
  (`apps/agenstra/frontend-agent-console`) and Loadweaver (`apps/loadweaver/frontend-console`). Landing pages are out
  of scope. This round only identifies problems; nothing is fixed.
- **How**:
  - Headless Chromium (Playwright 1193) against local dev servers (`nx serve … --configuration=development`) and the
    local Docker backends.
  - Sessions belong to dedicated demo accounts (`demo-*@example.test`) seeded with demo data (seed scripts in
    `/tmp/uiq/seed/`).
  - Viewports: 1440×900 desktop for every page, 390×844 phone for the main list / detail pages. Light theme
    everywhere, dark theme for one page per type.
  - Every screenshot was read by eye. A DOM probe (`/tmp/uiq/scripts/sweep.mjs`) records left edges of header / tab /
    head / cell / search, toolbar control heights, horizontal overflow, raw UUIDs / snake_case enums in visible text,
    and failing API calls.
- **Where**: screenshots in `/tmp/uiq/sweep/<app>/<nn>-<slug>[-phone|-dark].png`. Each app folder has an `index.md`
  (route → files) and a `probes.json`.
- **Conventions checked**: `.lw-plans/loadweaver.md` 3.38 (R1–R14, D1–D11) and the end of
  `.lw-plans/implementation.md`. Findings that contradict a decided convention are marked **[conv]**.
- **Severity**: preliminary, from the sweep. **Rating** is left empty for the user and the coordinator.
- Loadweaver areas currently in rework (resource create / edit → modals, plan "Apply progress" as a row, network
  effects / compiler diagnostics as columns) are marked **(area in rework)**.
