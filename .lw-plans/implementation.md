## Ground rules applied (section 6)

- Generators first (`@forepath/code`), domain `loadweaver`, tags `domain:loadweaver` / `scope:*` / `type:*`.
- Reuse shared libs before writing new code; new code instead of reuse gets a written reason (below, "Reuse decisions").
- New npm deps: `--save-exact`; `.npmrc` untouched (`ignore-scripts`, `min-release-age=7`).
- Verify loop per unit: format, lint, typecheck/build, tests (affected), security self-review, code review, docs.
- Resource care (WSL, 23 GB RAM, 12 cores, shared with running Agenstra containers): Nx `--parallel=2`, jest `--maxWorkers=2`, no long-lived extra containers.
- Nx output buffers in `tmp/nx-agent/`.

#### Built-in registry + Garage — implementation decisions (within 3.20 / 3.22)

- Garage `v2.4.1` and Distribution `registry:3.1.2`, digest-pinned; both verified locally: Distribution's S3 driver on Garage (path-style, region `garage`) works as pull-through cache, Docker pulls via a loopback registry without TLS (127.0.0.0/8 is insecure-by-default).
- Garage refuses to change `replication_factor` on an existing layout (verified). So the object store has **generations**: rf = min(3, members); an rf change starts a new Garage cluster (alternate ports), copies all objects (live pass, then registry read-only + delta pass), switches consumers, retires the old one. Same-rf membership changes are plain Garage layout changes (Garage rebalances).
- Garage holders = control-plane members plus draining former members until Garage no longer holds data there (leave guard like volumes).
- Garage / registry secrets (RPC secret, admin token, S3 key, HTTP secret) are HKDF-derived from the cluster's `ENCRYPTION_KEY` per generation and injected at push time only (never in desired-state rows).
- Registry: one Distribution instance for private images (`registry.lw/<project>/<repo>`, token auth with CP-signed ES256 JWTs carrying an x5c chain to the cluster CA) and one pull-through instance per configured mirror host (Cluster `registry.mirrors`, default Docker Hub, GHCR, Quay, registry.k8s.io, gcr.io, mcr, public ECR). Images from other hosts are pulled directly (plan warning).
- Nodes: the agent runs a pull router on `127.0.0.1:<port>` that forwards to the members' instances over the overlay (failover across members); workload images are rewritten to `127.0.0.1:<port>/<host>/<repo>@<digest>` at container create. Private repos only for images of the node's own workloads, with a pull token the CP issues over the agent stream.
- Deployments may only use private images of their own project namespace.
- Registry status: Garage generations (create → provision → copy live/final → activate → retire; same-rf rebalance; leave guard), registry instances on members, node pull router, private image namespace per project, in-cluster digest pinning, uncached-host plan warning, `docker login` / `push` through the API (`/api/registry/token` with Basic → Bearer middleware, `/v2` streaming proxy, PAT scopes `registry:pull` / `registry:push`). Tests: CP integration with three real Garage nodes (generation 1 → 2 incl. copy), agent lab with real Garage + Distribution (token chain, forged CA rejected, private pulls through router, Docker Hub pull-through).
- **Blocked**: registry credentials as project secrets (private upstream registries). Needs `secrets.service.ts` to authorize pull-secret refs per node, but reading/editing files under `secrets` paths is denied by the session's permission settings. Design ready: Project `registryCredentials: [{ host, secret }]`; plan pins with them; nodes pull those images directly (never through the shared cache) with credentials fetched like other secrets.
- Finding: `DEFAULT_IMAGES.controlPlane` is `:latest` (our own image, pinned by the release bundle in M6 / 3.26).
