# Periodic reports

On the 1st of every month Loadweaver writes a report for the month that ended — one for the cluster and one per project — as a printable HTML page and as JSON. Reports are kept in the cluster's own object store and browsed as a file tree.

## Schedule

- The job queue of every control-plane member runs the coordinator `reports.coordinator` on the cron pattern `LOADWEAVER_REPORTS_CRON` (default `0 3 1 * *`, 03:00 UTC on the 1st).
- The coordinator enqueues one job per scope with an idempotent id: `report.cluster.<yyyy>-<mm>` and `report.project.<project>.<yyyy>-<mm>`.
- Each job claims its scope and month in the database first. A month that is already completed (or being generated by another member) is skipped, so every report is written once even though every member runs the schedule. Failed jobs retry 3 times with backoff; a failed report can be claimed again.
- Admins can run a report again for a finished month (below); that replaces its files.

## Content

| Section         | Cluster report                                                                                                       | Project report                                  |
| --------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| Health          | share of the month in each state of the cluster's [health](./overview-and-health.md)                                 | the same for the project                        |
| Uptime and SLOs | availability over the month of every service with an availability [SLO](./slos-and-status-pages.md), with its target | the project's services                          |
| Incidents       | incidents open during the month (all projects)                                                                       | the project's incidents                         |
| Changes         | plans applied, rolled back, failed rollbacks; health changes                                                         | the same for the project                        |
| Capacity        | memory in use per day against today's capacity, and when a least-squares trend reaches 90 %                          | —                                               |
| Policy denies   | denied packets in the month                                                                                          | —                                               |
| Usage           | —                                                                                                                    | requested CPU, memory and storage at generation |

- The HTML is self-contained and printable: no scripts, no external resources, every value escaped.
- `report.json` holds the same data.
- Backups / restore tests and upgrades are listed as "not in this report yet".

## Storage

Reports go through the shared file storage (scope `loadweaverReports`, path segment `loadweaver/reports`):

```
loadweaver/reports/cluster/2026/09/report.html
loadweaver/reports/cluster/2026/09/report.json
loadweaver/reports/projects/shop/2026/09/report.html
```

On the members the API uses `FILE_STORAGE_PROVIDER=garage` by default: the active [object-store](./built-in-registry.md) generation's bucket `lw-files`, with its own access key derived from the cluster's encryption key (the registry's key can't read it). The key and bucket are created per generation, also for clusters formed before reports existed, and the bucket is copied together with the registry bucket when the object store moves to a new generation.

An operator can choose another provider through the control-plane role's environment:

| Variable                  | Values                                                                                                     |
| ------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `FILE_STORAGE_PROVIDER`   | `garage` (members' default), `local`, `s3`                                                                 |
| `FILE_STORAGE_ROOT`       | base directory for `local`                                                                                 |
| `FILE_STORAGE_S3_*`       | bucket, keys, region, endpoint, … for `s3` (see `libs/domains/shared/backend/util-file-storage/README.md`) |
| `LOADWEAVER_REPORTS_CRON` | cron pattern of the coordinator (UTC), default `0 3 1 * *`                                                 |

While the object store isn't active yet, report jobs fail and retry.

## File tree and downloads

The file tree is built from the recorded reports, not by listing the storage: only files of completed reports the caller may read are reachable, and nothing else in the storage is.

```bash
curl 'https://<control-plane>/api/reports/files?path=projects/shop/2026' -H "Authorization: Bearer $TOKEN"
```

```json
[{ "name": "09", "path": "projects/shop/2026/09", "type": "folder" }]
```

- Paths are relative (`cluster/…`, `projects/<project>/…`); `..`, `.` and NUL bytes are rejected, surrounding slashes ignored.
- Downloads are sent as attachments (`Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`), never rendered in the console's origin.
- A folder downloads as a ZIP archive of up to 500 files and 100 MiB (`413` beyond).

## Who may do what

| Caller                      | Read                        | Run again                   |
| --------------------------- | --------------------------- | --------------------------- |
| any cluster role            | cluster reports             | —                           |
| `cluster-admin`             | cluster and project reports | cluster and project reports |
| `auditor`, `infra-operator` | cluster and project reports | —                           |
| project `admin`             | their projects' reports     | their projects' reports     |
| other project members       | their projects' reports     | —                           |

Personal access tokens need `cluster:read` to list and download, `projects:admin` to run.

## API

| Request                                 | Meaning                                                                                    |
| --------------------------------------- | ------------------------------------------------------------------------------------------ |
| `GET /api/reports`                      | reports the caller may read, newest month first: scope, month, status, files with SHA-256  |
| `POST /api/reports/run`                 | `{"scope": "shop", "year": 2026, "month": 9}`: queue a report for a finished month (`202`) |
| `GET /api/reports/files?path=`          | folder entries (folders first)                                                             |
| `GET /api/reports/files/download?path=` | one file                                                                                   |
| `GET /api/reports/files/archive?path=`  | a folder as ZIP (empty path: everything visible)                                           |
