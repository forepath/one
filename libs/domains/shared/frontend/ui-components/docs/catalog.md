Global SCSS (load once after Bootstrap in app `styles.scss`): `styles/index.scss` (scrollbar, utilities, charts, controls, density, …).

**Data lists (3.38 D1–D11)**: every record collection is an `fpc-data-table`: State column first (`type: 'state'`, `state(row)` → `{ label, tone, icon?, severity? }`, square icon badge, severity sort), name column (`required`, `priority: 1`, `rowLink` → real link; a rich name template renders inside it), column `priority` 1 / 2 / 3 (container queries; stacked cards below 36 rem with check · state · name + priority-1 fields · ⋮), `paging` `client` / `server` (`total` or `hasNext`) / `infinite` (Agenstra tickets only: `hasMore` + `loadMore`), `[(page)]` / `[(pageSize)]` (25), `persistKey` (columns, sort, page size in localStorage), `groupBy`, `rowInlineActions`, `error`, skeleton while `loading`, `nested`. **Density**: `FpcDensityService` (compact by default, `localStorage` `fpc.density`, `set()` / `toggle()`) puts `fpc-density-compact` on `<body>`; `styles/_density.scss` tightens list items, lane / page headers and summary cards, and `fpc-tree` / `fpc-data-table` / `fpc-object-header` follow it. Apps that never inject the service keep today's spacing. Modal / icon-button / sidebar-popover chrome ship with their components. Do not reintroduce copies under `libs/domains/shared/frontend/*.scss`.

**Layers (z-index)**: `styles/_z-index.scss` defines `--fpc-z-*` (raised 1, sticky-local 2, dropdown 1000, sticky 1020, chrome 1030, top-bar 1032, offcanvas 1044/1045, modal-backdrop 1050, modal 1055, popover 1070, tooltip 1080, toast 1090; Bootstrap-aligned). In-content sticky heads / tab bars stay on raised / sticky-local (tab bars isolate Bootstrap's `.btn-group` z-index); `fpc-top-bar` / `fpc-sidebar` carry explicit chrome layers (never `isolation: isolate` without z-index on overlay hosts). App shells call `provideFpcOverlayPortal()` so `fpc-modal`, `fpc-context-menu` and `appendTo="body"` dropdowns render at `<body>` level (`FpcBodyPortal`); specs keep overlays inline unless they provide it.

**UI conventions (Loadweaver 3.38, all apps)**: edges have one owner (page wrapper top; header / tab bar / summary / toolbar strip / lane header their bottom; columns their right except the last; list rows their separator) — no manual `border-*` / `border-0` / `rounded-0` hacks; one 1 rem inset per column; no structural `position: sticky` (flex columns, one scroller per column; sticky only for table heads / feet and `fpc-list-header` rows inside it); toolbars / breadcrumbs in `fpcBoardLaneToolbar`, pagers in the lane / table footer; alerts `[flush]` (`m-3` only in modals); lanes have an empty state (`sm`) and a loading `fpc-empty-state`; no-matches (`icon="search"`) replaces the list; action order Views → secondary (`dark`) → Refresh → primary (rightmost), row actions edit `warning` → neutral `dark` → delete `danger`; modal footer [Cancel `dark`, Primary]; search placeholders `Search <plural noun>`; tabs only for alternative views of the same thing (collections → lanes).

**Control heights**: one height per size tier for every control that can share a row, from `styles/_controls.scss`: `--fpc-control-height-sm` (2.0234rem = natural `btn-sm` / `form-control-sm`; 1.875rem compact), `--fpc-control-height-md` (2.5625rem; 2.25rem compact), `--fpc-control-height-lg` (natural `btn-lg`), `--fpc-control-height-header` (2.35rem; 2.125rem compact). `.btn` (incl. raw buttons, `.btn-group` segmented toggles, `fpc-tab-group` options), `.form-control` / `.form-select` (not textarea / file / multiple), `.input-group-text` and `.pagination .page-link` derive their block padding from the resolved tier (`--fpc-control-h`), so single-line controls land exactly on it and wrapped labels still grow; `p-0` / `py-*` utilities keep winning. Icon-only `fpc-button` is square at its tier (`xs` stays 1.5rem); `fpc-search-field` / `fpc-typeahead-select` strips are the tier tall (bordered strips include the border), `fpc-pager` arrows, numbered pages, "Page x" and page-size select share it (`size="sm"` -> sm tier), the filter-panel toggle matches the md search strip, lane-header rows are at least sm tall, `fpc-panel` footers at least sm + padding. Inside `fpc-page-header` / `fpc-object-header` heads `--fpc-control-height-sm` is remapped to the header tier, so `sm` text buttons, selects and icon-only actions match there (menus inside keep sm). A lone `fpc-badge` inside `fpc-button` (chip-as-control) is sm tall; a count badge next to a label keeps the normal button chrome. Rule of thumb: one `size` per row; never mix `size="sm"` with default controls or raw `.btn` with a different size class in the same toolbar.

**Table heads**: every Bootstrap `.table` head cell (`thead > tr > th`, plain tables and `fpc-data-table`) gets one look from `styles/_tables.scss`: 0.875rem / 600 / 1.25rem line height, no wrap, middle-aligned, `--bs-tertiary-bg` (also when sticky); tune via `--fpc-table-head-bg` / `-font-size` / `-font-weight` / `-line-height`. **Cell padding**: every body / foot cell of a console `.table` (with or without `table-sm`) and `fpc-data-table` has one uniform padding on all sides per global density: `--fpc-table-cell-padding-y/-x` = 0.5rem normal, 0.25rem on `body.fpc-density-compact` (`FpcDensityService`); head cells take the mode's horizontal padding but keep `--fpc-table-head-padding-y` (0.5rem) in both modes (head height constant); `fpc-panel flush` still insets the first / last column to 1rem. Zero specificity (`:where`), so do not add `small` / `text-body-secondary` / `fw-*` on head rows; marketing tables opt out with `.fpc-table--plain-head`. Sortable heads use `<th aria-sort="none|ascending|descending"><button type="button" class="fpc-table__sort">Label <i class="fpc-table__sort-icon bi …" aria-hidden="true"></i></button></th>`: the button inherits the cell completely, the indicator's space is always reserved (shown on hover / focus and while sorted; end-aligned columns put it before the label), focus-visible ring. `fpc-data-table` renders exactly that.

**Sticky tables**: `fpc-data-table` (inputs above) and, for plain Bootstrap tables, the global classes `.fpc-table--sticky-head` / `.fpc-table--sticky-foot` (`styles/_tables.scss`: opaque cells incl. striped / hover / dark, edge line as inset shadow, `--fpc-z-sticky-local`). Sticky works against the nearest scroll container, so make the lane / panel body that one container for both axes and drop `.table-responsive` wrappers: `fpc-board-lane [scrollX]` (Loadweaver `loadweaver-lane scrollX`), `fpc-panel [scroll]` (body `overflow: auto`; height from the panel's flex share or `--fpc-panel-scroll-max-height`), or the `.fpc-scroll-both` utility (`--fpc-scroll-both-max-height`). Wide comparisons: `.fpc-table--sticky-first` keeps the first column in view. `.fpc-table--inset` gives a plain edge-to-edge table the 1 rem first / last cell inset (automatic for `fpc-data-table` and tables directly in a lane body), e.g. one table per `fpc-list-header` group. That container needs a bounded height: `fpc-board-lane` fills its flex column (`flex: 1 1 auto`), a list with a pager uses `fpc-panel class="flex-grow-1" scroll` (the `fpcPanelFooter` pager stays pinned below the scrolling body, like the `fpc-data-table` pager below its scroller). Safety net: a `.table-responsive` directly around a sticky table is reset to `overflow: visible` and a scrolling lane body holding one scrolls sideways too.
